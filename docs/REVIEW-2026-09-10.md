## Batch D — architecture (Architect roadmap)

Phase 1 "Trust the ground" (S/S–M, independent): bridge handshake (`ready` carries schema, capabilities, page `ytcfg` client version, selector health); audit lines to `.notice` + in-memory journal so a diagnostics export grades with `fieldcheck.sh`; harness in CI + `RiffCore` SwiftPM package + nightly anonymous InnerTube canary; event-driven resume/jump waits; extract Prefs/SleepTimer/SessionSnapshot/TrackExtras/PageCommands from `PlayerBridge` (≈750 lines, guard counts untouched).

Phase 2 "One authority, for real": page-native Play Next via the page's own `queueAddEndpoint` action (synthetic `ytmusic-menu-service-item-renderer` click first, command resolver second, informed by the `queueApi:` probe), verified by store presence **and** player agreement on the next advance; then Phase D deletion in the documented order; `PlaybackContext` value type and `QueueReconciler`; fake-page seam so field captures become replay tests.

Phase 3 "Seamless by construction": SPA navigation instead of `location.href` (click-to-play without reload); InnerTube retry/backoff/single-flight/offline; energy (store subscription instead of the 2s poll, 1Hz progress); persistence consolidation; release stamping and notarization.
